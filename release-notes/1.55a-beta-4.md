# 1.55a-beta-4

- Automatically respect Better Combat's active windup and recovery in guard presentation, shield use and Punchy animation ownership. No new toggle is added.
- Observe each successful Better Combat windup, including hold-to-attack repeats, instead of relying only on the initial button press. Failed swing attempts do not repeatedly create attack locks.
- Let an eligible held guard take over after the current swing and required cooldown finish, deferring the next held-input attack. A fresh Attack press can leave guarding. Guarding does not automatically cancel a windup.
- Preserve confirmed-feint recovery and actual-hit cooldown checks. Vanilla attacks, mining and unsupported optional API versions retain the input fallback.
- Consolidate swing and feint handling in GuardBetterCombatCompat and BetterCombatGuardMixin. Remove the retired feint-only files when applying the source overlay.

Config defaults, saved presets, UI, particle assets and server combat calculations are unchanged. Payload protocol remains 69.

This patch does not add server-side lag compensation. High ping can still affect actual parry registration.

Validation: Java grammar, local class imports/access, packet constructor arities, unchanged combat/config/asset comparisons and input decision traces checked. No Java compilation or Minecraft execution was performed. Test hold-to-attack, both buttons held, fresh Attack presses and valid feints with Better Combat and Punchy installed.
