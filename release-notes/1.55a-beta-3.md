# 1.55a-beta-3

- Start eligible local guard poses, shield raising, movement slowdown and the meter without waiting for the server response. Damage, blocking, retaliation, healing and parry results remain server-controlled.
- Associate guard input, status replies and combat feedback with an attempt ID. A reply for a released or superseded guard cannot restore its pose or interrupt a newer attempt. A rejected attempt corrects its local presentation; holding the key does not repeatedly retry it.
- Continue the locally displayed parry window when acceptance arrives; do not restart the pose or repeat the input. Share hand-selection priorities and synchronize the server's consecutive-hand count.
- Give Attack immediate priority over local guarding and its Punchy poses, including pending reactions and returns. Use configured Attack and Guard mappings rather than mouse-button numbers.
- Restrict Better Combat feint recovery to a cancelled windup. Wait for Attack release before restoring readiness, and clear pending recovery when a newer attack starts.
- Add input IDs and attack/feint transitions to guard diagnostics. Keep prediction state bounded and invalidate old attempts on death, player replacement and disconnect.

Network protocol: 69. Both clients and server must use this version. Config and saved-preset formats are unchanged.

This patch adds presentation prediction, not server-side lag compensation. Network delay can still affect actual parry registration.

Validation: Java source grammar, packet codec symmetry, constructor arities, cross-class access, unchanged combat/asset comparisons and prediction-state traces checked. Prediction traces interpret the source AST; no Java compilation or Minecraft execution was performed. Multiplayer and animation behavior require in-game testing.
